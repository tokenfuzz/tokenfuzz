Summary¶

The SLICE handler copies a [offset, offset+length) window out of the whole input stream into a scratch buffer and checksums it. It validates only that the start offset is within the stream, never that offset + length is, so a window that begins near the end and requests up to 512 bytes reads past the end of the heap-allocated input buffer. A single SLICE field with off equal to the stream length and want = 0x0200 reaches it directly. The attacker reads out-of-bounds heap memory into ctx->slice_sum; the checksum is an observable side channel that can leak adjacent heap contents. The missing check is at rcfg.c:141, the over-read at rcfg.c:147.

Root Cause¶

handle_slice reads off and want as big-endian u16 from the field value (rcfg.c:138-139). It guards only if (off > stream_len) return; (rcfg.c:141), which permits off == stream_len and any off <= stream_len. It then copies n = min(want, 512) bytes with memcpy(window, stream + off, n) (rcfg.c:146-147). The assumed invariant — "the copy stays inside the stream" — requires off + n <= stream_len, but only off is bounded. With off = stream_len and want = 512, memcpy reads 512 bytes starting one past the end of the input buffer (which the CLI heap-allocated to the exact file size, rcfg_cli.c:29). ASan reports a 512-byte heap-buffer-overflow read 0 bytes after the input region, frame handle_slice.

Impact¶

Any decoder of untrusted RCF streams is exposed to an out-of-bounds heap read of up to 512 bytes past the input buffer. The bytes flow into a checksum the caller can read back, making this an information-disclosure oracle over adjacent heap memory (potential leakage of heap metadata, pointers, or other records) in addition to a crash under ASan.

Fix Direction¶

Validate the full window: after reading off and want, reject unless off <= stream_len && want <= stream_len - off (computed without overflow), or clamp n to min(want, stream_len - off). Bounding off alone cannot constrain the copy length.

Severity rationale¶

Severity is the CVSS v4.0 score — one industry-standard metric, computed by the vendored FIRST reference scorer. Base metrics come from the primitive and surface, with Attack Vector/Requirements also reflecting the trigger's caller-control facts (a trusted local API/call-sequence reads as AV:L/AT:P). The Threat metric (E) is read locally, not from threat intelligence: it grades how far this audit got toward proving the bug — a reproducer that fires is E:P, an unproven argument is E:U — so a demonstrated bug outranks a written one. FIRST defines E against public exploit availability, which is not what is measured here, and nothing in this run is publicly disclosed. Read E as reproduction confidence. The Environmental Security Requirements (CR/IR/AR) are left Not Defined — they model a deploying organisation's asset importance, which the scorer cannot derive, so a generic score keeps the CVSS-B worst case. Environmental modified impacts are set only to floor impact where reachability facts justify it (non-shipping surfaces, caller-only triggers). Cluster size remains a priority/verification fact because CVSS v4.0 has no cluster metric.
